# One read-only call, and fetch prefers Bunny's 1080p MP4

On 20 October 2026 we checked six facilities in the PickleCam dashboard and Bunny's file headers. Only 1 of 6 libraries keeps the original upload, and that original is about 4 times the size of the MP4. Bunny's MP4 keeps dropped-frame gaps, rounded to a 1/30 s grid, so it carries the timing we need. Fetch therefore downloads the MP4 first, then the original, then the HLS stream, which also keeps PickleCam's bandwidth bill down. The endpoint is one call, a recording list that includes each MP4's download link. PickleCam builds the link, so a change to its link format or pull zone needs no change on our side, and a separate links call would add a round trip per video for nothing.
