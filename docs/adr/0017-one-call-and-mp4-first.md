# One read-only call, and fetch prefers Bunny's 1080p MP4

On 20 October 2026 we checked six facilities in the PickleCam dashboard and Bunny's file headers. All six libraries have a 1080p MP4, but only 1 of 6 keeps the original upload, and that original is about 4 times the size of the MP4. Bunny's MP4 keeps dropped-frame gaps, rounded to a 1/30 s grid, so it carries the timing we need. We download the MP4 first, then the original, then the HLS stream, which also keeps PickleCam's bandwidth bill down. The endpoint, built after the prototype (ADR 0018), is one call: a recording list that includes each MP4's download link. PickleCam builds the link, so a change to its link format or pull zone needs no change on our side, and a separate links call would add a round trip per video for nothing.
